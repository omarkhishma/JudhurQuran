- [2026-10-03] **The Analyser reads Quranic text from the corpus and everything else against the Quran's own words, never with an invented analysis (P4.3, ANA-Q01).** — A verse reference, a range of up to ten verses, or a phrase found in exactly one verse is the corpus's gold analysis at its place (confidence 1.0, the place linked). Other words: the same written form in the Quran, its analyses ranked by their share of those occurrences (the share is the confidence, one candidate per root, three at most); else after taking off conjunctions, prepositions, the article and attached pronouns (×0.7; after the article no verb reading, from the corpus or a verb pattern); else root candidates from the Quran's patterns over its roots (at most 0.35); function words are particles with no root. Inflection (case, mood, person) is shown and exported only for a word read at its Quranic place: a form borrowed from another occurrence says nothing about the reader's sentence. The reader's choice among candidates is kept per written form on the device (feeding the review queue waits for P7); Punctuation and signs at a word's edges are not part of it. CoNLL-U is tokenised as UD Arabic: proclitics (conjunctions, prepositions, the future «سَ») and object or possessive pronouns are words of their own under a multiword-token range, from the corpus's segments for a Quranic word and from the clitics read for a free one; the article stays on its word (Definite=Def); a verb's first suffix stays on the verb when it agrees with it in person, number and gender (QAC splits subject suffixes, UD Arabic does not); participles carry VerbForm=Part and their voice, verbal nouns VerbForm=Vnoun; Root, Pattern, Source, Confidence and the place in MISC; one sentence per verse. - [2026-10-03] **Sync (P6.2, P6.5) works record by record per store, against a shadow of what this device last agreed with the account (`jadhr-sync`: hashes, never the records).** — A record whose hash differs from its shadow changed here, stamped when first seen so an offline edit keeps its time; one in the shadow but gone here was deleted here (a tombstone). A store syncing for the first time sends records with their own times (a note's last edit, a card's last review) or 1, so a first sign-in lets the account's choices win for word states and settings and keeps the device's as replaced versions (the sign-in sheet says exactly this, F7); the server treats a version identical to its own as a no-op and a tie with a different value as a loss kept in history. Safety (audit 11): more deletions in one store and one run than max(10, a quarter of its synced records) are held, and the reader is asked on whatever page they are on to remove them everywhere or bring them back (F11); a store this browser cannot read (an IndexedDB read error) fails its loading instead of reading as empty, is never written over, and stays out of sync until a read works (F11); maps and texts are found by their own keys, and their indexes change in one transaction (F12); a record the server refuses (too large, a full account) stays changed here and the Profile says how many (F14); a pull that says `full` (the device is behind the purged deletions) reads what it agreed and no longer finds as deleted elsewhere (F6); records on a device that came from another account (`jadhr-owner`) go into a new account only on the reader's word — add them, or start the device with the new account's data (F8). Device-local: the panel's width, folds and open rails, the theme, the trail of this visit, recent words. The journal syncs only when turned on: one record per day, text and device, every root met (`rm:`), the last place looked up (`ctx`, `cc`), and turning it off removes all of it from the server (F3); the furthest verse read and roots met merge by max and min. Deleting this device's data stops sync after the run in progress, freezes every store in the tab, signs out first so the account keeps everything, and tells the other tabs (`jadhr-wiped`), which reload (F15). Tabs stay in step: localStorage's storage event, and a BroadcastChannel for IndexedDB stores that ignores its own tab.

### Architecture
- [2026-10-02] **Next.js 16 App Router + React 19 + TypeScript for the web.** — SSR is required for verse/root/word pages (Arabic SEO is the clearest market gap per research 04), and the reader/editor are client-heavy.
- [2026-10-02] **Previous caching model (fetch revalidate + tags), not Cache Components; a release expires the `dataset` tag.** — Stable with next-intl's static rendering; content is immutable per release. The loader POSTs to the web's `/api/revalidate` (bearer `JADHR_REVALIDATE_SECRET` in production) which calls `revalidateTag("dataset", { expire: 0 })` — not stale-while-revalidate, because a release can change payload shape and stale pages then crash. API ETags hash `version@loaded_at`, re-read every 30 s, so a corrected rebuild of the same version never answers 304 with old content. A CDN in front must be purged on release (runbook).
- [2026-10-02] **Nothing is prerendered at build: every page renders on first request and is cached (ISR) until the next release expires it.** — A code deploy never needs the database or API, and the web image builds in CI with no data. First visits cost one render; all later ones are cached. Sitemap ids are fixed (capacity 80k words) for the same reason.
- [2026-10-02] **Production topology: Caddy in front (TLS, compression, `/api/v1` straight to FastAPI, `/api/revalidate` not public), Next standalone, Postgres; one-off loader container.** — Verified end to end on local Docker (docs/DEPLOY.md).
- [2026-10-02] **CSP allows inline scripts but no eval or third-party origin (audio from EveryAyah only).** — Next hydrates through inline scripts; a nonce would make every page dynamic and lose ISR.
- [2026-10-02] **FastAPI (Python) API + Python pipeline, separate from the web app.** — Owner suggested Python; the public API is a product (versioning, OpenAPI docs, own limits); the Arabic data tooling is Python. The browser reaches the API same-origin through a Next rewrite of `/api/v1/*`.
- [2026-10-02] **Search on Postgres (normalised shadow columns + pg_trgm), behind one module.** — Quran scale does not need a search cluster; all Arabic search assertions pass. Revisit when lexicon/hadith full-text relevance is measured to need OpenSearch.
- [2026-10-02] **Two Arabic search shadows: imlāʾī (KFGQPC "emlaey" text aligned per word) and Uthmani-stripped; the query picks one.** — Everyday spelling matches the imlāʾī shadow (الصلاة → ٱلصَّلَوٰة); text pasted from a mushaf (detected by dagger alef, wasla or Quranic marks) matches the Uthmani shadow. Lemmas also carry a heuristic plain spelling (وٰ→ا etc.) for matching only.
- [2026-10-02] **Graph canvas: @xyflow/react + elkjs, bounded expansion.** — The handoff editor is rich editable DOM cards; scale is handled by bounding, not a canvas renderer.
- [2026-10-03] **Every Quran permalink lands in the one reader: `/quran/{s}` reads, `/quran/{s}/{a}` opens the verse in the panel, `/word/{s:a:w}` opens the word; verse mode writes its path to the address bar, a word stays `?w=&at=` on the sūra.** — One reader, one URL behaviour (RDR-566). The sūra text, metadata, JSON-LD and share images render on the server; the panel's tafsir and entry render in the browser (search engines that run scripts index them). Rendering the panel on the server would need per-request state outside the module stores.
- [2026-10-03] **The reader's star writes to the one saved list (`jadhr-saved`, kind `lemma`, keyed by slug) that Saved, the Review count and later the Notebook read.** — The prototype kept stars under one key and read them under another (RDR-520).
- [2026-10-02] **Postgres 17 in Docker for dev (host 5442); web dev on port 3210, API on 8000.** — Match prod major; port 3000 belongs to another of the owner's projects.

- [2026-10-03] **A signed-in reader's private maps stay sealed sync records; a server-side graph document exists only for a map shared for comments or published (P8.1-E, research 13).** — Maps already sync record by record with key and value sealed (audit 11 F2); a plain `graphs` table would put every private map in the clear on the server. - [2026-10-04] **A reader's own text is named `user:<id>` (`user:<id>:<passage>:<word>` within it), the Quran's `quran:2:255:3` in the reader's namespace; where the reader is in it is kept under that name (the old `text:<id>` moved there when the browser's data is read, and when another device sends it), and the export of the texts carries each one's identifier (P1.7a).** — The reader's texts are private and live in the browser, so the identifier names without opening anything to anyone else; it keeps a reader's text from ever sharing a name with a text of the library.

- [2026-10-04] A new file written with a shell redirect (`cat > e2e/digits.spec.ts`) replaced an existing spec of the same name — its fourteen tests of the language's digits gone until the commit's status line said `M`, not `A`. Before writing a new file by shell, test that the name is free (`test -e`), and read a commit's status letters before committing.
- [2026-10-03] xyflow answers Enter, Space and Escape on a focused card by selecting it when it is not selected: after our Escape cleared the selection, its own handler — run later in the same keydown, after React had applied ours — selected the card again. Keys the editor owns are taken in the capture phase and stopped there; Enter is left to xyflow only for a focused card not yet selected.
- [2026-10-03] Playwright's "Desktop Chrome" device reports Windows, so xyflow expects Ctrl to add to a selection, while on a Mac Ctrl-click opens the context menu; ⇧-click, which the design asks for anyway, works the same everywhere.
- [2026-10-03] A zoom step taken from `getZoom()` during the previous step's animation multiplies a value in flight (reset to 100 % then + read 188 %); step from where the last step was going.

- [2026-10-03] A nested layout under `[locale]` must call `setRequestLocale` itself: without it the site header's `getTranslations` reads the request, and every prerendered page under that layout answered 500 (DYNAMIC_SERVER_USAGE) while the dynamic ones worked.

- [2026-10-03] The React compiler's lint refuses a render prop that is handed an object holding callbacks that read refs; hand such tools down through a context instead, read by the components rendered around the canvas.

- [2026-10-03] xyflow deletes a card in two changes — its wires, then the card — and calls both handlers synchronously from one render; a controlled map that commits in each handler loses one of them (the wires came back in the stored map). Commit deletions once, in `onDelete`, which receives both.
