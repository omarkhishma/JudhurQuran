- [2026-10-03] **The Analyser reads Quranic text from the corpus and everything else against the Quran's own words, never with an invented analysis (P4.3, ANA-Q01).** — A verse reference, a range of up to ten verses, or a phrase found in exactly one verse is the corpus's gold analysis at its place (confidence 1.0, the place linked). Other words: the same written form in the Quran, its analyses ranked by their share of those occurrences (the share is the confidence, one candidate per root, three at most); else after taking off conjunctions, prepositions, the article and attached pronouns (×0.7; after the article no verb reading, from the corpus or a verb pattern); else root candidates from the Quran's patterns over its roots (at most 0.35); function words are particles with no root. Inflection (case, mood, person) is shown and exported only for a word read at its Quranic place: a form borrowed from another occurrence says nothing about the reader's sentence. The reader's choice among candidates is kept per written form on the device (feeding the review queue waits for P7); Punctuation and signs at a word's edges are not part of it. CoNLL-U is tokenised as UD Arabic: proclitics (conjunctions, prepositions, the future «سَ») and object or possessive pronouns are words of their own under a multiword-token range, from the corpus's segments for a Quranic word and from the clitics read for a free one; the article stays on its word (Definite=Def); a verb's first suffix stays on the verb when it agrees with it in person, number and gender (QAC splits subject suffixes, UD Arabic does not); participles carry VerbForm=Part and their voice, verbal nouns VerbForm=Vnoun; Root, Pattern, Source, Confidence and the place in MISC; one sentence per verse. A curriculum needs expert review (PLAN §8), so the copy calls the order computed and invites a teacher's review rather than presenting it as a syllabus. For the owner: whether a teacher should reorder the early lessons.

- [2026-10-03] **A browser that refuses to save is told on every page, once, until dismissed, with the export offered (RDR-444, NTB-Q01).** — The reader's two-second toast was the only notice, and only in the reader; a failed save loses work at reload.

- [2026-10-03] **Sync (P6.2, P6.5) works record by record per store, against a shadow of what this device last agreed with the account (`jadhr-sync`: hashes, never the records).** — A record whose hash differs from its shadow changed here, stamped when first seen so an offline edit keeps its time; one in the shadow but gone here was deleted here (a tombstone). Push in chunks of at most 500 records and about 4 MB, take the server's version where it refused, pull from the cursor, apply where this device has not changed the same record. A store syncing for the first time sends records with their own times (a note's last edit, a card's last review) or 1, so a first sign-in lets the account's choices win for word states and settings and keeps the device's as replaced versions (the sign-in sheet says exactly this, F7); the server treats a version identical to its own as a no-op and a tie with a different value as a loss kept in history. Safety (audit 11): more deletions in one store and one run than max(10, a quarter of its synced records) are held, and the reader is asked on whatever page they are on to remove them everywhere or bring them back (F11); a store this browser cannot read (an IndexedDB read error) fails its loading instead of reading as empty, is never written over, and stays out of sync until a read works (F11); maps and texts are found by their own keys, and their indexes change in one transaction (F12); a record the server refuses (too large, a full account) stays changed here and the Profile says how many (F14); a pull that says `full` (the device is behind the purged deletions) reads what it agreed and no longer finds as deleted elsewhere (F6); records on a device that came from another account (`jadhr-owner`) go into a new account only on the reader's word — add them, or start the device with the new account's data (F8). Device-local: the panel's width, folds and open rails, the theme, the trail of this visit, recent words. The journal syncs only when turned on: one record per day, text and device, every root met (`rm:`), the last place looked up (`ctx`, `cc`), and turning it off removes all of it from the server (F3); the furthest verse read and roots met merge by max and min. Deleting this device's data stops sync after the run in progress, freezes every store in the tab, signs out first so the account keeps everything, and tells the other tabs (`jadhr-wiped`), which reload (F15). Tabs stay in step: localStorage's storage event, and a BroadcastChannel for IndexedDB stores that ignores its own tab.

- [2026-10-03] **Accounts (P6.1, P6.5): a sign-in link by e-mail that works once and only when the reader presses the button on the page it opens, Google and Apple only where configured, a session as a bearer token kept with the account in `jadhr-auth` — no cookie; the token is a secret and never in an export.** — D3. The sheet says what this browser holds and that nothing needs an account, and offers the export instead (HUB-F02); no button pretends (the prototype's ORCID and Institution buttons called a fake sign-in). Apple's answer, posted to `/api/auth/apple`, is passed on to the page that finishes signing in; the PKCE verifier stays in the tab, and a browser that keeps nothing there fails the start plainly (F19). A link spent on page load was used up by mail gateways that open links to check them (F17). The page says the link's period the API reports (`/auth/providers` → `link_minutes`).

### Architecture
- [2026-10-02] **Next.js 16 App Router + React 19 + TypeScript for the web.** — SSR is required for verse/root/word pages (Arabic SEO is the clearest market gap per research 04), and the reader/editor are client-heavy.
- [2026-10-02] **Previous caching model (fetch revalidate + tags), not Cache Components; a release expires the `dataset` tag.** — Stable with next-intl's static rendering; content is immutable per release. The loader POSTs to the web's `/api/revalidate` (bearer `JADHR_REVALIDATE_SECRET` in production) which calls `revalidateTag("dataset", { expire: 0 })` — not stale-while-revalidate, because a release can change payload shape and stale pages then crash. API ETags hash `version@loaded_at`, re-read every 30 s, so a corrected rebuild of the same version never answers 304 with old content. A CDN in front must be purged on release (runbook).
- [2026-10-02] **Nothing is prerendered at build: every page renders on first request and is cached (ISR) until the next release expires it.** — A code deploy never needs the database or API, and the web image builds in CI with no data. First visits cost one render; all later ones are cached. Sitemap ids are fixed (capacity 80k words) for the same reason.
- [2026-10-02] **Production topology: Caddy in front (TLS, compression, `/api/v1` straight to FastAPI, `/api/revalidate` not public), Next standalone, Postgres; one-off loader container.** — Verified end to end on local Docker (docs/DEPLOY.md).
- [2026-10-02] **CSP allows inline scripts but no eval or third-party origin (audio from EveryAyah only).** — Next hydrates through inline scripts; a nonce would make every page dynamic and lose ISR.
- [2026-10-02] **FastAPI (Python) API + Python pipeline, separate from the web app.** — Owner suggested Python; the public API is a product (versioning, OpenAPI docs, own limits); the Arabic data tooling is Python. The browser reaches the API same-origin through a Next rewrite of `/api/v1/*`.
- [2026-10-02] **Search on Postgres (normalised shadow columns + pg_trgm), behind one module.** — Quran scale does not need a search cluster; all Arabic search assertions pass. Revisit when lexicon/hadith full-text relevance is measured to need OpenSearch.
- [2026-10-02] **Two Arabic search shadows: imlāʾī (KFGQPC "emlaey" text aligned per word) and Uthmani-stripped; the query picks one.** — Everyday spelling matches the imlāʾī shadow (الصلاة → ٱلصَّلَوٰة); text pasted from a mushaf (detected by dagger alef, wasla or Quranic marks) matches the Uthmani shadow. Lemmas also carry a heuristic plain spelling (وٰ→ا etc.) for matching only.
- [2026-10-02] **Graph canvas: @xyflow/react + elkjs, bounded expansion.** — The handoff editor is rich editable DOM cards; scale is handled by bounding, not a canvas renderer.
- [2026-10-03] **Every Quran permalink lands in the one reader: `/quran/{s}` reads, `/quran/{s}/{a}` opens the verse in the panel, `/word/{s:a:w}` opens the word; verse mode writes its path to the address bar, a word stays `?w=&at=` on the sūra.** — One reader, one URL behaviour (RDR-566). The sūra text, metadata, JSON-LD and share images render on the server; the panel's tafsir and entry render in the browser (search engines that run scripts index them). Rendering the panel on the server would need per-request state outside the module stores.
- [2026-10-03] **The reader's star writes to the one saved list (`jadhr-saved`, kind `lemma`, keyed by slug) that Saved, the Review count and later the Notebook read.** — The prototype kept stars under one key and read them under another (RDR-520).
- [2026-10-02] **Postgres 17 in Docker for dev (host 5442); web dev on port 3210, API on 8000.** — Match prod major; port 3000 belongs to another of the owner's projects.

- [2026-10-03] **A signed-in reader's private maps stay sealed sync records; a server-side graph document exists only for a map shared for comments or published (P8.1-E, research 13).** — Maps already sync record by record with key and value sealed (audit 11 F2); a plain `graphs` table would put every private map in the clear on the server. Comments and publishing need a shared document, so only those maps get one, by the reader's act.

- [2026-10-04] **The editorial board's work lives in its own schema (`editorial`: entries, reviews, log) and is read beside the content at request time, never written into `content.*` (P3.0, research 14).** — A release replaces `content.*` whole; work keyed by stable keys (a root's key, a slug, an extracted row's id) survives it. Two people in the database itself: a trigger refuses a decision by the entry's author and a second approval of one revision by one person, whatever the API does.
- [2026-10-04] **What the board approves is shown beside the source, never over it: a gloss, a function, a plain explanation and a sense list credited to the board; a reviewed or corrected row keeps the book's words with the verdict (and the correction) beside them; a rejected row is left out.** — Law L2 and the review mechanics of P7: the reader always sees who said what. Rejected rows are extraction errors (a heading taken for a meaning), so showing them marked would still mislead.
- [2026-10-04] **Public payloads name the board, never its members.** — The log keeps who wrote and who approved each revision, and the workbench shows it to the board; a reader needs the board's accountability, not editors' names, and editors are private people until the owner decides otherwise (D15).
- [2026-10-04] **An approval clears the API's short cache of the small kinds, asks the web to expire its cached pages through the loader's own endpoint (in the background), and changes every content ETag, which now covers the board's state (its latest approval and how many are in force) beside the release.** — Without them a page cached until the next release would show the board's work a day late, and a browser holding a payload would be answered "not modified" until the next release; the ETag alone left that bug in the first cut, caught by reading `cached()`. A browser's own copy may still be up to an hour old (max-age); if the web's expiry call fails, its pages expire on their own and nothing approved is lost.
- [2026-10-04] **A source names its work by the id the content tables give it; the API resolves the title for the reader, and the workbench offers the known ids and says when one is unknown.** — The reader saw "lane 5:2138"; it should see the book. Two candidate buttons cited ids no table knows ("corpus", "muyassar") and now cite `qac-wbw` and `kfgqpc-muyassar-gharib`.

- [2026-10-04] **A shared map is read by anyone with its link; its comments are read and written by those signed in; a mention names only someone who has spoken on the map (the owner or a commenter), by the name they chose — never an address (P8.1-E).** — The link is the owner's to hand out, as a copy link already is; comments are a conversation among accounts, and a mention list of everyone who merely opened the map would show their names to strangers.
- [2026-10-04] **Each save to a shared copy names the revision it was made from; a save over a newer one (the owner's other device) is refused and the owner chooses — open the shared copy here, or keep their work as a new map. Nothing is merged.** — The handoff's PUT sends whole documents (08 §8.6) and D5 chose presence, not concurrent editing; a merge of two whole maps would silently lose one side's work. Writes to the browser's copy go one at a time, so recording the new revision never overtakes a save.
- [2026-10-04] **A map's history: for a shared map, the server keeps a version at most every ten minutes of editing (the last hundred); for a private one, this browser keeps them the same way (the last thirty), unsynced. Restoring is one undoable step (EDT-259).** — The server never reads a private map (the decision of 2026-10-03), so its history cannot live there; ten minutes keeps the history readable and small while the undo stack covers the minutes between.
- [2026-10-04] **Notifications are in the product: My maps counts each shared map's open and new comments and those that mention the reader. No e-mail.** — Mail to other people goes out only on the owner's word, and the mail service is the owner's to set up; an opt-in mention e-mail is proposed (B40).
- [2026-10-04] **A deleted comment that others replied to stays as a mark so its thread still reads; one without replies goes. Deleting an account takes its comments the same way. Deleting a shared map from My maps stops sharing it.** — A thread whose first comment vanished would read as replies to nothing; a reader who leaves takes their words with them; a map deleted by its owner should not live on under a link.

- [2026-10-04] **A meaning map draws only the classical books' own relations, and as the map's own only once the editorial board has reviewed them; the extracted ones are listed as such and go on a map only as the reader's own link, drawn dashed (P8.4, research 15).** — L2 and L3: no relation is inferred, and none is shown as settled before an editor has read it; a reader who wants an unreviewed one can still use it, marked. ## Lessons

- [2026-10-03] xyflow answers Enter, Space and Escape on a focused card by selecting it when it is not selected: after our Escape cleared the selection, its own handler — run later in the same keydown, after React had applied ours — selected the card again. Keys the editor owns are taken in the capture phase and stopped there; Enter is left to xyflow only for a focused card not yet selected.
- [2026-10-03] Playwright's "Desktop Chrome" device reports Windows, so xyflow expects Ctrl to add to a selection, while on a Mac Ctrl-click opens the context menu; ⇧-click, which the design asks for anyway, works the same everywhere.
- [2026-10-03] A zoom step taken from `getZoom()` during the previous step's animation multiplies a value in flight (reset to 100 % then + read 188 %); step from where the last step was going.

- [2026-10-03] A nested layout under `[locale]` must call `setRequestLocale` itself: without it the site header's `getTranslations` reads the request, and every prerendered page under that layout answered 500 (DYNAMIC_SERVER_USAGE) while the dynamic ones worked.
- [2026-10-03] Keyframes are global by name: a second `@keyframes dc-rise` in the editor's styles replaced the reader's, and the reader's toast jumped (RDR-523's test caught it). Name a component's keyframes after it.
- [2026-10-03] The React compiler's lint refuses a render prop that is handed an object holding callbacks that read refs; hand such tools down through a context instead, read by the components rendered around the canvas.

- [2026-10-03] xyflow deletes a card in two changes — its wires, then the card — and calls both handlers synchronously from one render; a controlled map that commits in each handler loses one of them (the wires came back in the stored map). Commit deletions once, in `onDelete`, which receives both.
- [2026-10-03] A React Query cache set to never go stale outlives the page that read it: a document opened again by a client-side link came from the first read and autosave wrote it back over newer work. Read an editable document afresh on every mount (`gcTime: 0`), and test a reopen by the app's own links, not by `page.goto`, which reloads and hides the fault.
- [2026-10-03] For a click inside the graph canvas, Playwright's "scrolling into view" does not pan the canvas, and xyflow's focus pan moves only a card wholly out of view; a test about a card's button presses it directly. And Tailwind's layered `!important` beats an unlayered `!important` (the cascade reverses for important declarations), so a test stylesheet that hides a utility-styled element uses a property the utility does not set.

- [2026-10-03] Turning a message into rich text («<term>…</term>») breaks every caller still using plain `t()`: it prints the tag on screen. Batch 3 left three such callers of the corpus credit, found only in a screenshot. `src/lib/messages.test.ts` now fails on any tagged message passed to `t()`.
- [2026-10-03] Match words in the Shamela typings with final yāʾ and alif-hamza folded: they write «والثانى»، «فى»، «الاول», so a marker list in standard spelling silently found the first aṣl and never the second. Build matchers from words through one helper that allows ي/ى, أ/ا and harakāt between letters.

- [2026-10-03] Never chain a commit after a test run piped through `grep`: the pipe's status is grep's, so two failing e2e tests let the commit through. Run the tests, read the result, then commit.

- [2026-10-03] The web's fetch cache outlives builds and restarts (`.next/cache`): an API endpoint whose payload changed shape keeps answering the page with the old shape for a day — /sources crashed on a missing field. After an API change on an existing URL, run `uv run python -m jadhr_api.loader --revalidate` against the server in use; a production server refuses without its `JADHR_REVALIDATE_SECRET`, so the local test server is started with a local one.

- [2026-10-03] Check the fonts against the text, not the text against the fonts: «عزّ وجلّ» (U+FDFF, Unicode 14) is in 1,809 dictionary articles and in neither Plex nor Amiri, so it drew as a box.
